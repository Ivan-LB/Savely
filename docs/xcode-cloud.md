# Xcode Cloud for Savely

Written 2026-08-18. Savely's first upload (build 1) was archived from a beta
Xcode and App Store Connect refused it: "Esta compilación utiliza una versión
beta de Xcode y no se puede enviar." This Mac only has Xcode-beta installed,
so every archive from here has the same problem. Xcode Cloud archives on
Apple's machines with a released Xcode, which makes the local beta irrelevant.

The long version, with the wrong turns and how each was found, is Fave's
`docs/xcode-cloud.md` (same author, same week). This file keeps only what is
different for Savely and the settings that matter. Where Fave's notes say
**observed once**, nothing here upgrades that.

## What is different from Fave

| Fave | Savely |
|---|---|
| Project is generated by XcodeGen, not committed | `Savely.xcodeproj` and its shared scheme are committed. No generation step, no XcodeGen, no scheme patch. |
| Secret is `Config/Secrets.xcconfig` (TMDB key), gitignored | No build-time secret. `Savely/Config.plist` (OpenAI key, gitignored) stopped being a Resources build input in 1.1, so a clean checkout builds as-is. |
| An archive without the key is refused | The Tips feature is behind `FeatureFlags.tipsEnabled = false` and has no safe key source (a key in a bundled plist can be lifted from the IPA). Any archive with the flag `true` is refused. |

`ci_scripts/ci_post_clone.sh` now only enforces that gate. Until 1.1 it also
wrote `Savely/Config.plist` from a SECRET `OPENAI_API_KEY` variable (or a
placeholder); that ended with `docs/plans/drop-bundled-config-plist.md`.

The workflow needs no environment variables. Do not add `OPENAI_API_KEY`
back: when Tips returns, the key lives behind a proxy, not in the build.

## Workflow settings

Created from Xcode via **Integrate > Create Workflow…** (Xcode 26 and 27; older
Xcodes put it under Product).

- **Environment: a released Xcode.** The field arrives preselected on
  whatever Xcode created the workflow, and from Xcode-beta that is a beta,
  which is the exact thing App Store Connect rejects. Fave shipped on 26.6
  (17F113).
- **Actions: Archive - iOS**, Deployment Preparation set so the build lands
  in App Store Connect / TestFlight. A plain Build compiles and leaves nothing
  to upload.
- **Start conditions: manual only.** The default "every push to the branch"
  archives on every push and eats the 25 monthly compute hours.
- **Build number** comes from the workflow counter at App Store Connect >
  Xcode Cloud > Ajustes > Número de la compilación, NOT from
  `CURRENT_PROJECT_VERSION`. Build 1 is already taken by the rejected beta
  archive, so set the counter to 2 before the first run. A rejected upload
  wants a new build, not "Recompilar", because a rebuild can reuse the number
  that was just refused.
- The `Savely` scheme's Test action includes `SavelyUITests`, which needs a
  Simulator with the seed and takes minutes. Do not add a Test action to the
  archive workflow; `.github/workflows/ci.yml` runs unit tests on every PR.

## Export compliance

`Savely/Info.plist` declares `ITSAppUsesNonExemptEncryption = false`. Savely
ships no cryptography of its own; the only network call is HTTPS through
URLSession, which is exempt. With the key present, App Store Connect skips
the per-upload encryption questionnaire.

## What still cannot be done from this Mac

Anything that needs a released Xcode locally: archiving, and the
`xcrun altool` / Transporter upload path. Xcode Cloud replaces both. Building,
testing and running on the Simulator with the beta is fine and is what every
verification in this repo did.
